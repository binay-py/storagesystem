# Sanduk Backup for iOS

A small native iPhone/iPad app that backs up the Photos library to a Sanduk chest in the background.
It uses the same encryption as the web app (`public/app.js`): HKDF-SHA256 key derivation, AES-GCM-256,
18 MB encrypted chunks, an encrypted name and an encrypted thumbnail. Files it uploads open normally in the
web app, and the Worker needs no changes.

## What it does

- Uploads the photos and videos in the library, newest first. Edited photos are sent as edited, and
  Live Photos go up as photo + video, paired the same way the web app pairs them.
- Skips anything already in the chest (by SHA-256, the same dedupe as the web app), and resumes
  interrupted multi-chunk uploads through `/files/resume`.
- Can fetch originals from iCloud ("Optimize iPhone Storage" is fine).
- Wi-Fi-only switch. On by default, and Low Data Mode counts as mobile data.
- Background work:
  - **BGProcessingTask**: long runs, usually overnight while charging. This does most of the work.
  - **BGAppRefreshTask**: about 30 s a few times a day, for a handful of new photos.
  - **"Back Up to Sanduk" Shortcuts action**: use it in a Personal Automation (for example "When charger
    is connected → Run Immediately"). This is the most dependable trigger.
  - iOS decides when background tasks run. No third-party app gets continuous background
    access to Photos.
- The chest key is kept in the Keychain (this device only, readable after first unlock) and never sent anywhere.
  Only the derived auth token goes to the server.

## Build (on the Mac)

```bash
brew install xcodegen
cd ios
xcodegen            # creates SandukBackup.xcodeproj from project.yml
open SandukBackup.xcodeproj
```

1. **Signing & Capabilities**: choose your Team, and change the bundle id
   (`com.sanduk.backup.personal`) to one you own. The background task ids follow the bundle id
   automatically.
2. Run the tests (⌘U). `CryptoCompatTests` checks the Swift crypto against vectors generated by
   the browser's WebCrypto using the web app's code. If they pass, uploads are compatible.
3. Run the app on a real iPhone (the Simulator has no real Photos library or background tasks).

No Mac with XcodeGen? Create a new iOS App project in Xcode (SwiftUI, Swift) named `SandukBackup`,
delete its generated Swift files, drag in everything under `Sources/`, then add the Info.plist keys
listed in `project.yml` (photo usage text, `UIBackgroundModes` = processing + fetch, and
`BGTaskSchedulerPermittedIdentifiers`).

## Testing background runs from Xcode

With the app running from Xcode, send it to the background, pause the debugger, and in the lldb console run:

```
e -l objc -- (void)[[BGTaskScheduler sharedScheduler] _simulateLaunchForTaskWithIdentifier:@"<bundle id>.backup"]
```

Then continue. The backup starts as if iOS had launched the task.

## Publishing notes

- **Only for yourself or family?** TestFlight internal testing (up to 100 people on your team, builds last
  90 days) or a Development/Ad Hoc install avoids App Review entirely.
- **App Store review** needs a working **demo server address and chest key** in the review notes,
  because the app does nothing without a Sanduk server. Use a separate test chest, not your real key.
- **Export compliance**: the app encrypts user data with AES-GCM via Apple's CryptoKit. App Store Connect
  asks about this on upload. `ITSAppUsesNonExemptEncryption` is intentionally not set, so the
  question comes up for you to answer.
- **Privacy**: `PrivacyInfo.xcprivacy` declares UserDefaults (CA92.1) and file timestamp/size (C617.1). The app
  collects nothing for the developer. Photos go only to the server the user enters, already encrypted.

## Files

| File | What it is |
|---|---|
| `Sources/Crypto.swift` | Key derivation, AES-GCM, content hash (matches app.js) |
| `Sources/SandukAPI.swift` | Worker API client + retry policy |
| `Sources/Uploader.swift` | Photos asset → encrypted chunks, thumbnail, live pairing |
| `Sources/BackupEngine.swift` | What to upload, progress, done-list, stop rules |
| `Sources/SandukBackupApp.swift` | App entry + background task registration/scheduling |
| `Sources/BackupIntent.swift` | Shortcuts action |
| `Sources/ContentView.swift` | Setup + status screen |
| `Tests/CryptoCompatTests.swift` | WebCrypto compatibility vectors |
